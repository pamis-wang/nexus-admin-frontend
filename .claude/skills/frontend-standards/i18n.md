# 多語系（vue-i18n）

> 來源：development-standards — `frontend-standards/13.多語系規範.md`

只適用**有 `src/locale/` 的專案**（採用 vue-i18n，繁中＋英文）；沒有的專案畫面文字照原本寫中文，不要自行加裝。完整規範與理由在 `13.多語系規範.md`，這份只放照做的步驟與範例。

---

## 新增畫面文字的步驟

1. **先找既有的 key**：通用動作（儲存、取消、編輯）、對話框標題、項次／操作表頭在 `common`，共用驗證訊息在 `validation`（專案有的話）。有就用，不開同義的新 key。
2. **模組專屬的文字放模組命名空間**：`pages/UserManagement/` ↔ `user.json`，命名空間用 camelCase。新命名空間要在 `zh-TW/index.ts` 與 `en-US/index.ts` 都 import。
3. **同一個 key 兩份 JSON 一起加**：繁中寫原文，英文照〈英文寫法〉。
4. 程式碼改用 `t('user.xxx')`，用法照〈怎麼用 `t()`〉。
5. 完成條件：`npm run lint`、`npm run type-check`、`npm run test` 都過，而且**切到英文實際看過**——畫面上沒有中文、沒有原樣顯示的 key。

```
src/locale/
├── index.ts          # 支援的語系、字典型別（以繁中為準）
├── zh-TW/
│   ├── index.ts      # import 各命名空間
│   ├── common.json   # 共用動作、對話框標題、通用表頭
│   ├── menu.json     # 選單與路由標題，key 用路由 name
│   ├── http.json     # 連線與 HTTP 錯誤的通用訊息
│   └── user.json     # 一個頁面模組一個命名空間
└── en-US/            # 與 zh-TW 同結構、同一組 key；少 key 時 type-check 失敗
```

## 模組命名空間的 key 分組

照這組名稱分，不自創同義分組：

| key | 放什麼 |
|---|---|
| `title`／`addTitle`／`editTitle`／`viewTitle` | 頁面標題（麵包屑與 `x-page-header` 共用） |
| `section.*` | 表單分區標題 |
| `field.*` | 表單欄位標籤 |
| `column.*` | 表頭 |
| `placeholder.*` | placeholder |
| `hint.*` | 欄位說明、提示文字 |
| `action.*` | 模組專屬的按鈕（`action.add` →「新增使用者」）；通用的「儲存」「取消」用 `common.action.*` |
| `status.*` | 狀態標籤 |
| `empty.*`／`loading.*` | 空狀態、載入中文字 |
| `option.*` | 下拉選項 |
| `validation.*` | 模組專屬的驗證訊息 |
| 不分組 | 通知與對話框訊息：`created`／`createFailed`／`updated`／`updateFailed`／`deleteConfirm`／`deleteTitle`／`deleted`／`deleteFailed`／`loadFailed` |

```json
{
  "title": "使用者管理",
  "addTitle": "新增使用者",
  "field": { "account": "帳號", "email": "電子信箱" },
  "column": { "account": "帳號" },
  "validation": { "accountRequired": "請輸入帳號" },
  "created": "使用者「{name}」已新增",
  "createFailed": "新增使用者失敗",
  "deleteConfirm": "確定要刪除使用者「{name}」嗎？此操作無法復原。",
  "selected": "已選 {n} 位使用者"
}
```

```json
{
  "title": "User Management",
  "addTitle": "Add User",
  "field": { "account": "Account", "email": "Email" },
  "column": { "account": "Account" },
  "validation": { "accountRequired": "Enter an account" },
  "created": "User \"{name}\" added.",
  "createFailed": "Failed to add the user.",
  "deleteConfirm": "Delete the user \"{name}\"? This can't be undone.",
  "selected": "{n} user selected | {n} users selected"
}
```

路由 `meta.title` 填 `menu` 字典的 key（用路由 `name`），不填中文；選單依 key 取目前語系的文字。

## 怎麼用 `t()`

- 元件與頁面：`const { t } = useI18n()`，放 `const` 區第一個（官方組合函式）。
- 元件以外（service、store、路由守衛）拿不到 `useI18n`，改用 `i18n.global.t`（`import { i18n } from '@/plugins/i18n'`）。
- 變數用具名參數：`t('user.created', { name: form.account })`。數量用複數寫法並直接傳數字：`t('user.selected', count)`。
- **會隨語系變的值放 `computed`**；模板裡直接寫 `t()` 就會跟著換，不用另外處理。

  ```ts
  // ❌ setup 時算一次，切換語系後表頭停在舊語言
  const columns: XTableColumn[] = [{ name: 'account', align: 'left', label: t('user.column.account'), field: 'account' }]

  // ✅
  const columns = computed<XTableColumn[]>(() => [
    { name: 'account', align: 'left', label: t('user.column.account'), field: 'account' },
  ])
  ```

  下拉選項、狀態對照表同理。`<script setup>` 以外的模組層常數只存 key，顯示時才 `t(key)`。
- 驗證規則是函式，驗證當下才呼叫 `t()`，不必 `computed`：`(value: string) => value.trim() !== '' || t('user.validation.accountRequired')`。
- 日期元件的月份與星期交給 Quasar 語言包，隨語系切換；`q-date` 不另傳 `:locale`。
- 不翻譯：logger 訊息、程式碼註解、測試描述、開發者展示頁、使用者自訂的資料（活動名稱、自訂的顯示名稱）、送到後端的值與權限識別字。
- 後端回傳的錯誤訊息不放進字典，處理方式見 `api-service.md`〈錯誤訊息〉。

## 英文寫法

先沿用字典裡既有的譯法，同一句中文只對應一種英文；專案有術語表時以術語表為準。

| 規則 | 用在 | 例 |
|---|---|---|
| **Title Case**，介系詞、冠詞、連接詞小寫 | 按鈕、頁面與區塊標題、選單、欄位標籤、表頭、對話框與通知的標題、狀態標籤 | Save、Back to List、Role Name、Loading Failed |
| **Sentence case**，完整句子加句點、片語不加 | 訊息內文、提示、placeholder、空狀態、確認問句 | Failed to load roles.、Enter your password、No data found |
| 組合詞照字面組 | X管理 → X Management、X設定 → X Settings、搜尋X → Search X、請輸入X → Enter X、載入X中 → Loading X…、X失敗 → Failed to ＜動詞＞ X、X成功／已X → X ＜過去分詞＞ | 更新角色失敗 → Failed to update the role、資源樹儲存成功 → Resource tree saved |
| 確認問句用簡短問句，不用 Are you sure | 刪除、離開等確認 | 確認是否刪除角色 → Delete this role? |
| 數量用複數寫法 | 含數字的文字 | `{n} feature \| {n} features` |
| 中英對照欄位 | 同一筆資料分中英文填的欄位 | 名稱(中)、名稱(英) → Name (Chinese)、Name (English) |
| 不用全形標點；省略號用單一字元 `…`；欄位冒號用共用的 `common.labelColon`（專案有的話） | 所有英文 | 載入角色中... → Loading roles… |

## 操作導覽（專案有導覽定義檔時）

導覽文字是資料，跟著定義檔（例如 `src/tours/*.json`）走、不放進字典：每段給使用者看的文字（名稱、分組、步驟標題與說明、提示）都寫成兩個語系的物件，中英文寫在同一處。

```json
{
  "name": { "zh-TW": "角色管理：看懂這個畫面", "en-US": "Role Management: Understand This Screen" },
  "groupName": null,
  "steps": [
    {
      "anchor": "role-result-table",
      "title": { "zh-TW": "「用戶人數」是改動前要先看的數字", "en-US": "\"Users\" is the number to check before you make changes" },
      "description": { "zh-TW": "這一欄是<strong>目前有多少人</strong>正在用這個角色。", "en-US": "This column shows <strong>how many people</strong> currently have this role." }
    }
  ]
}
```

- 新寫的導覽兩個語系一起寫。繁中不能空白；英文空字串只是過渡，畫面會退回顯示繁中。
- `description` 用 HTML 標籤排版（`<strong>`、`<br>`），不用 Markdown 的 `**粗體**`。
- `groupName` 對齊左側選單第一層，同一組的每份定義檔各語系要寫得一字不差；不分組填 `null`。

## 交付前逐條對過

- [ ] 模板與 script 都沒有寫死給使用者看的文字（通知、對話框、驗證訊息、表格欄位、下拉選項都查過）
- [ ] 新 key 繁中與英文兩份 JSON 都有，新命名空間兩個 `index.ts` 都登記
- [ ] 能用 `common`／`validation` 既有 key 的地方沒有另開新 key
- [ ] 英文照〈英文寫法〉：大小寫、句點、`…`、確認問句、複數
- [ ] 含 `t()` 的陣列（表頭、選項）用 `computed`
- [ ] 切到英文實際看過，沒有中文、沒有原樣顯示的 key
